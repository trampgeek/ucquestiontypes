Note to would-be editors

This is the object-oriented ("named robots") variant of the RoboTurtle question type. It is a separate fork of the original single-robot type, which students use through global functions like move(); here students create one or more RoboTurtle objects and call methods on them (alice.move()). Use the original type for single-turtle questions and this one only when you want students to work with objects.

It is a very complex question type with a lot of code replicated in the template and prototype extra fields. To edit, use the source code in the python3_roboturtle_oo directory of the ucquestiontypes repository. The functionality is broken into a dozen or so files and a build.py program is used to generate the content for the template and prototype extra fields - never edit prototypeextra.html, template.py, assembledrobot.py or editor.html directly, as they are all generated and will be overwritten.

About this question type

RoboTurtle uses the Python Turtle module to implement a variant of Reeborg's World - see https://reeborg.ca/reeborg.html. Students write code that drives one or more robots around a grid world to perform some task set by the question, such as moving to target cells, following exact paths, or collecting items and depositing them at one or more locations. Each robot has a name, shown under its starting cell, and the student's code must create a RoboTurtle for each robot by name - alice = RoboTurtle("Alice"). Every RoboTurtle object has its own position, heading, path and inventory, which is the point of the exercise: the same class, different state per instance.

Authoring RoboTurtle questions

IMPORTANT:
  1. You must choose this OO question type (not the original python3_roboturtle, which uses a different, incompatible test format and API). If the type is wrong you get confusing errors such as KeyError: 'path'.
  2. You must check TwigAll or you'll get inexplicable error messages (typically an "Unexpected token '{'" syntax error when the question loads)!
  3. You cannot (easily) enter the Answer (or the Preload) directly. You will need to Preview the question, use Ctrl+Alt+m to disable the UI, and copy and paste the answer from the preview back into the authoring form.
Use the visual world editor

Hand-writing the testcases JSON below is tedious and error-prone. There's a standalone visual editor at python3_roboturtle_oo/editor.html in the repository - download it and open it directly in a browser (it's self-contained; no server or build step needed). You click/drag to place walls, blocked cells, items, item dumps, paths and text-output expectations on a grid matching the live question's rendering. Robots are managed in the Robots panel: add as many as you like, give each a name, colour, start cell, heading and (for TargetWorld and PickUpItemsWorld) a target cell; the selected robot is the one the Robot start, Target cell and Draw path tools and the inventory-item buttons act on. Export produces the complete template parameters JSON, {"testcases": [...]}, ready to paste into the question's Template parameters field, and flags likely mistakes (duplicate names, two robots in one cell, a TargetWorld with no target, a robot with no path). Import accepts a previously exported test list - or a legacy single-robot test, in which case the robot is given the name "Alice".

(The original editor, python3_roboturtle/editor.html, produces a different format and must not be used for this question type.)

Template Parameters
  • testcases - a JSON list of one or more tests, as described below. REQUIRED. The Template parameters field holds a JSON object whose only required key is testcases, i.e. {"testcases": [ ...tests... ]}.
  • maxnumlines - the maximum number of (non-blank, non-comment, non-docstring) lines of code allowed in the student's answer. Optional, default 0 (no limit).
  • showhelpbutton - set to false to hide the in-question "RoboTurtle Help" button. Optional, default true.

Note that disabledfunctions, which the original question type supports, is not supported here.

What students can use

Students create a RoboTurtle object for each robot in the world and command it through methods. In the descriptions below, t stands for any RoboTurtle object, e.g. alice.

Creating a RoboTurtle
  • RoboTurtle(name) - take control of the robot with the given name (a case-sensitive string). Raises an error if there's no such robot, if a RoboTurtle for that robot already exists, or if the name is omitted when the world's robots are named (which, for worlds built with the editor, is always). Every robot in the world must have had a RoboTurtle created for it by the end of the student's code, or the test fails. (Only a hand-written test with a single robot and no name allows a bare RoboTurtle().)
Movement and actions
  • t.move() - move one cell forward. Raises an error if blocked by a wall, a blocked cell, or another robot.
  • t.turn_left() - rotate 90 degrees counterclockwise.
  • t.turn_right() - rotate 90 degrees clockwise.
  • t.take() - pick up an item from the current cell, add it to the inventory, and return its type name (e.g. 'star'). Raises an error if there's nothing to take.
  • t.put() - place the least-recently-picked-up item from the inventory into the current cell, and return its type name. Raises an error if the inventory is empty.
  • t.toss() - place the least-recently-picked-up item from the inventory into the cell directly in front of the robot, and return its type name. This works over a wall, which is what makes "throw it over the wall" questions possible. Raises an error if the inventory is empty or the target cell is out of bounds or blocked.
  • t.build_wall() - build a wall directly in front of the robot, i.e. at the edge of the current cell in the direction the robot is facing.
  • t.send_text(s) - display the string s, prefixed by the robot's name and a colon and space (e.g. Alice: Done), in a text bar below the grid (only the most recent call's text is shown). Only usable in tests whose world_params includes expected_texts - see "Text output", below. Raises an error otherwise.
  • t.speed(n) - set this robot's animation speed, from 1 (slow) to 10 (fast); 0 for fastest possible. Cosmetic only - has no effect on grading. There is also a global function speed(n) that sets the speed of all robots (it is what the speed selector under the display uses).
  • t.print_state() / print(...) - print diagnostic output to the on-screen output pane. Browser-only: both are silently disabled during actual grading on the Jobe server, so they're useful for a student debugging their own code in the preview, but must never be relied on as part of a test's pass/fail logic. Use send_text() for anything that needs to be checked.
State-checking boolean methods
  • t.at_goal() - true if the world's goal is currently satisfied, for all robots (reached their targets, and/or matched their required paths, and/or emptied all items into their dump(s), depending on world type).
  • t.front_is_clear() - true if the robot is able to move forward (no wall, blocked cell or other robot in the way).
  • t.right_is_clear() - true if the cell to the right is clear.
  • t.wall_in_front() - true if there's a wall directly in front.
  • t.wall_on_right() - true if there's a wall to the right.
  • t.object_here() - true if there's an item in the current cell.
  • t.carries_object() - true if the inventory is non-empty.
  • t.is_facing_north() - true if the robot is currently facing north.
State-query methods
  • t.position() - the robot's current grid coordinates as an (x, y) tuple.
  • t.facing() - the robot's current heading as 'N', 'S', 'E', or 'W'.
  • t.target_cell() - the first robot's target cell as an (x, y) tuple, or None if this world has no target.
  • t.inventory() - a list of the type names of items currently in this robot's inventory, ordered by when they were picked up (most recently picked up last).

The testcases format

The testcases template parameter must be a JSON list of one or more tests. Each test is a JSON object shaped like this (comments added here for explanation - real JSON can't contain comments, so strip them if copying this by hand; using the visual editor avoids the problem entirely):

{
  "world_class": "TargetWorld",       // one of TargetWorld, PathWorld, PickUpItemsWorld - see "Types of World" below
  "world_params": { },                // parameters specific to world_class, plus optionally cell_size and expected_texts - see below
  "grid_size": [10, 8],               // [width, height] in cells (NOT [rows, columns])
  "robots": [                         // one entry per robot, in the order that matters for the plain "targets"/"paths" forms below
    {"name": "Alice", "position": [0, 0], "heading": "east", "colour": "blue"},
    {"name": "Bob", "position": [9, 0], "heading": "west", "colour": "red"}
  ],
  "walls": [],                        // list of [[x1,y1],[x2,y2]] pairs, each horizontal or vertical
  "blocked_cells": [],                // list of [[x0,y0],[x1,y1]] rectangle corner pairs (bottom-left, top-right)
  "items": []                         // see below
}

Each robot has:

name
The string students pass to RoboTurtle(...). Names are case-sensitive and must be unique, and are drawn under the robot's starting cell. Optional only for a single hand-written robot (default "robot", drawn only if there are several robots), but the editor always sets one.
position, heading
Starting cell and one of "north", "south", "east", "west".
colour
Colour of the robot and its trail, as a turtle colour name. Optional; the defaults, in robot order, are blue, red, green, orange, purple.

For backward compatibility the old single-robot form "robot_start": {"position": [0, 0], "heading": "north"} is still accepted in place of robots; the one robot is then unnamed. Don't use it for new questions.

Each entry in items looks like:

{
  "type": "leaf",         // an item type - see "Item types" below
  "position": [5, 7],     // a cell, or the string "inventory" to start in a robot's inventory
  "count": 3,             // how many such items at that cell/in inventory. Optional, default 1
  "robot": 0              // only for "inventory": the index (0, 1, ...) in "robots" of the robot that carries it. Optional, default 0
}

These world_params entries apply regardless of world_class:

cell_size
Cell size in pixels. Optional, default 65.
expected_texts
See "Text output", below.
labelled_cells
A list of [[x, y], icon] pairs drawing fixed decorative icons in cells (they have no effect on grading). icon is an item type or "house_outline".

Text output

Any world type can require the student's code to produce a specific sequence of messages via send_text(). Add expected_texts to world_params - an ordered list of the exact strings that must be displayed, in order, e.g. ["Alice: Starting", "Bob: Done"]. Note that send_text() prefixes each message with the sending robot's name, a colon and a space, so the expected strings must include that prefix. This reserves a text bar below the grid (showing only the most-recently-sent message) and makes at_goal()/the pass condition additionally require exactly that sequence. A handy pattern is to combine this with the return values of take()/put()/toss(), e.g. alice.send_text(f"Picked up {alice.take()}").

Item types

Available item type names (used for items, target_icon, dump icon/type, and labelled_cells): star, key, leaf, house, home, flag, trash, box, target, banana, apple. (home is a synonym for house.) Icons only - not usable as items - can also be house_outline, a faint grey line drawing of a house that a turtle can sit on top of without obscuring it.

Types of World

The world_class determines the goal the student must satisfy to pass a test. In all of them, robots may not move into each other's cells, so coordinating several robots is part of the problem.

TargetWorld

Each robot that has a target must finish on it.

World Parameters:

targets
A list of targets. Each entry is either {"robot": "Alice", "location": [6, 0]} (the robot is identified by name - the editor always writes this form), or just a cell [6, 0], in which case it applies to the robot at the same position in the robots list. A robot without a target is unconstrained. At least one target is required.
target
A single target cell, for the first robot. Shorthand for a one-entry targets.
target_icon
The icon used to mark target cells - typically 'flag' (chequered), 'target' (dart-board), 'house'/'home', or 'house_outline' (faint grey outline; useful when the target is also where a robot starts, as in "changing houses"). Optional, default 'flag'.
target_labels
When there are several robots each target is labelled with a small "→name" in its robot's colour, bottom right of the cell. Set to false to switch the labels off (e.g. when the question text says who goes where). Optional, default true.

PathWorld

Each robot that has a required path must follow it exactly, cell by cell, from its start cell to its finish.

World Parameters:

paths
A list of required paths. Each entry is either {"robot": "Alice", "path": [...]} or just the list of segments, which then applies to the robot at the same position in robots. A path is a list of path segments; each segment is a two-element list of 2-element locations (start and end of that segment) and must be horizontal or vertical. A robot without a path isn't graded. Paths aren't drawn on the grid, so the question text has to describe them.
path
A single path, for the first robot. Shorthand for a one-entry paths.

PickUpItemsWorld

The robots must collect all items in the grid (except explicitly excluded ones), optionally redepositing them at one or more dump locations. A subclass of TargetWorld, so it also accepts targets, but targets are optional here: if there are none, only the items matter.

World Parameters:

item_dumps
A list of dump specifications, each a dictionary with keys:
  • location - the dump's grid cell. Required.
  • type - the item type that must end up there, e.g. 'leaf'. Optional, default 'Any' (accepts any item type).
  • icon - the item type used to draw the dump's icon, e.g. 'trash' or 'box'. Optional, default 'trash'.
  • count - how many items are expected at the dump. Optional - if omitted, it's auto-derived as the number of matching items (of type, or all items if 'Any') in the world or in any robot's starting inventory for this test, so e.g. "put all the leaves in the trash" doesn't need hand-counting them.
A dump whose type isn't 'Any' fails separately if any wrong-typed item ends up there, as well as if the count is wrong. If item_dumps is omitted entirely, it's only required that no items remain anywhere in the grid (i.e. they're all in the robots' inventories).
exclude_cells
A list of 2-element locations of cells whose items the robots do not need to gather (ignored by the check).

Worked examples

Changing houses. A TargetWorld in which two robots must swap ends of a corridor that is blocked except for one side bay. Neither robot can pass the other without one stepping into the bay. The targets are each other's start cells, drawn as faint houses with no target labels.

{
  "testcases": [
    {
      "world_class": "TargetWorld",
      "world_params": {
        "targets": [{"robot": "Alice", "location": [6, 0]}, {"robot": "Bob", "location": [0, 0]}],
        "target_icon": "house_outline",
        "target_labels": false
      },
      "grid_size": [7, 2],
      "robots": [
        {"name": "Alice", "position": [0, 0], "heading": "east", "colour": "blue"},
        {"name": "Bob", "position": [6, 0], "heading": "west", "colour": "red"}
      ],
      "blocked_cells": [[[0, 1], [2, 1]], [[4, 1], [6, 1]]],
      "items": []
    }
  ]
}

Throw it over the wall. A PickUpItemsWorld in which Alice starts carrying three stars, a wall splits the corridor, and the trash can (Bob's side) is walled off from Bob's home. Both robots must finish at home. Alice has to toss() the stars over the vertical wall, and Bob has to collect them, go home, and toss() them over the small wall into the trash can. The dump's count is derived automatically from Alice's inventory.

{
  "testcases": [
    {
      "world_class": "PickUpItemsWorld",
      "world_params": {
        "targets": [{"robot": "Alice", "location": [0, 0]}, {"robot": "Bob", "location": [7, 0]}],
        "target_icon": "house_outline",
        "target_labels": false,
        "item_dumps": [{"location": [7, 1], "icon": "trash"}]
      },
      "grid_size": [8, 2],
      "robots": [
        {"name": "Alice", "position": [0, 0], "heading": "east", "colour": "blue"},
        {"name": "Bob", "position": [7, 0], "heading": "west", "colour": "red"}
      ],
      "walls": [[[4, 0], [4, 1]], [[7, 1], [8, 1]]],
      "blocked_cells": [[[0, 1], [6, 1]]],
      "items": [{"type": "star", "position": "inventory", "count": 3, "robot": 0}]
    }
  ]
}
